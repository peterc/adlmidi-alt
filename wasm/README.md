# ADLMIDI-ALT-WEB

A static MIDI player using the ADLMIDI engine compiled to WebAssembly.
Audio synthesis runs in an AudioWorklet; no backend or JavaScript packages are required.

## Run

Build the engine first (see below), then serve this directory over HTTP on
localhost or HTTPS elsewhere. For example:

```sh
python3 -m http.server 8000
```

Open `http://localhost:8000` and press **Play**. Opening `index.html` with `file://`
is not supported.

## Use

- Open MIDI files, a folder, or a direct URL. Files and folders can also be
  dropped anywhere. Each selection replaces the playlist; local files are not uploaded.
- Click a playlist entry or use Previous/Next. Playback advances automatically;
  **Loop** repeats the current track. Dropped files and URL loads start playback.
- Remote URLs must allow cross-origin requests (CORS).
- Settings control the instrument bank, OPL3 card count, gain, synthesis, and reverb.
  Bank, card count, and synthesis changes restart the track.
- File info shows embedded metadata. Channel meters show estimated levels;
  virtual MIDI devices share the 16 displayed rows.

Standard MIDI formats 0 and 1 with PPQ timing and RMI wrappers are supported.
Limits: 8 MiB per file, 256 tracks, and 500,000 events. Browsers may require a
Play tap to enable audio. Older iOS versions may require Silent mode to be off;
background playback depends on the browser.

## Build

Requires Python 3 and Emscripten (`em++` on `PATH`). Run from this directory:

```sh
./build.sh
```

The build uses the source snapshot in `vendor/` and produces `engine.mjs` and
`engine.wasm`. `src/engine.cpp` is the handwritten adapter; the other files in
`src/` are generated by `prepare.py`.

The included Copper Circuit MIDI is the default demo. If optional local demo
files are present in `assets/`, the build uses those instead. Those files and
generated build outputs are excluded from Git.

To update the snapshot from the parent repository's engine and rebuild:

```sh
./build.sh --refresh-vendor
```

Review build errors after engine updates: the extraction code may need adjusting.
`vendor/source.json` records the source revision and hashes.

## Test

Requires Node.js and Python 3. Build first, then run:

```sh
node tests/engine.test.mjs
node tests/metadata.test.mjs
node tests/playlist.test.mjs
python3 tests/verify-vendor.py
python3 tests/package.test.py
```

Browser tests additionally require `agent-browser` and a running local server.
Pass its URL explicitly:

```sh
python3 tests/browser-smoke.py http://localhost:8000
python3 tests/playlist-browser.py http://localhost:8000
python3 tests/url-browser.py http://localhost:8000
```
